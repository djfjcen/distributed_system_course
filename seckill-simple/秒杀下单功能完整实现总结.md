# 秒杀下单功能完整实现总结

## 概述
基于 Spring Boot + Kafka + Redis + MySQL 的分布式秒杀系统实现。

---

## 核心要求实现清单

| 需求 | 实现状态 | 说明 |
|------|--------|------|
| 消息队列 | ✅ | Kafka 消息队列，主题 `seckill-orders` |
| Redis 缓存库存 | ✅ | 快速库存扣减，key 前缀 `inventory:` |
| Kafka 异步处理订单 | ✅ | 消费者异步创建订单记录 |
| 削峰填谷 | ✅ | 消息队列缓冲，异步消费控制速率 |
| 雪花算法订单 ID | ✅ | 64bit 分布式 ID，支持分布式扩展 |
| 按用户 ID 查询订单 | ✅ | GET /api/orders/user/{userId} |
| 按订单 ID 查询 | ✅ | GET /api/orders/{orderId} |
| 按商品 ID 查询订单 | ✅ | GET /api/orders/product/{productId} |
| 幂等性：防止重复下单 | ✅ | Redis 防重机制，同一用户同一商品只能秒杀一次 |
| 数据一致性：防超卖 | ✅ | Redis 缓存检查 → 本地缓存扣减 → 数据库最终一致 |

## 代码文件清单

### 1. 数据模型
#### `entity/Order.java`
```
- id (BIGINT PK)：雪花 ID
- userId (BIGINT)：用户 ID
- productId (BIGINT)：商品 ID
- quantity (INT)：购买数量
- price (DECIMAL)：订单价格（冻结快照）
- status (INT)：订单状态（0=pending, 1=success, 2=cancelled）
- createdAt, updatedAt：时间戳
- 索引：user_id, product_id, (user_id, product_id) UNIQUE
```

### 2. 核心业务逻辑
#### `util/SnowflakeIdGenerator.java`
- 64bit ID：1(sign) + 41(timestamp) + 10(datacenterId+workerId) + 12(sequence)
- 支持 1024 个数据中心 + 工作进程
- 每秒可生成 409.6 万 ID

#### `service/OrderService.java`
**核心方法：`seckillOrder(userId, productId, quantity)`**
1. 检查幂等性：Redis 键 `order:idempotent:{userId}:{productId}` 防重
2. 检查商品存在性
3. 检查库存（Redis 缓存优先）
4. 扣减 Redis 库存
5. 生成雪花 ID + 创建本地订单（状态=pending）
6. 发送 Kafka 消息

#### `mq/producer/SeckillOrderProducer.java`
```java
public void sendOrderMessage(SeckillOrderMessage message) {
    // 序列化为 JSON
    // 消息 key：{userId}_{productId}（保证同用户同商品顺序消费）
    kafkaTemplate.send(TOPIC, key, messageJson);
}
```

#### `mq/consumer/SeckillOrderConsumer.java`
```java
@KafkaListener(topics = "seckill-orders", groupId = "seckill-group")
public void consume(String message) {
    // 反序列化 Kafka 消息
    // 更新订单状态为 success
    // 扣减数据库库存（最终一致性）
}
```

### 3. API 接口
#### `controller/OrderController.java`
- `POST /api/orders/seckill?userId={userId}`：下单
  - 请求体：`{productId, quantity}`
  - 响应：订单对象或错误信息
  
- `GET /api/orders/{orderId}`：按 ID 查询
- `GET /api/orders/user/{userId}`：按用户查询
- `GET /api/orders/product/{productId}`：按商品查询

### 4. DTO
#### `dto/order/SeckillOrderRequest.java`
```java
@NotNull Long productId;
@NotNull @Min(1) Integer quantity;
```

#### `mq/message/SeckillOrderMessage.java`
```java
Long orderId, userId, productId, timestamp;
Integer quantity;
BigDecimal price;
```

### 5. 数据库
#### SQL
```sql
CREATE TABLE orders (
    id BIGINT PRIMARY KEY,
    user_id BIGINT NOT NULL,
    product_id BIGINT NOT NULL,
    quantity INT NOT NULL,
    price DECIMAL(10, 2) NOT NULL,
    status INT NOT NULL DEFAULT 0,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    INDEX idx_user_id (user_id),
    INDEX idx_product_id (product_id),
    UNIQUE INDEX idx_user_product (user_id, product_id)
);
```

## 工作流程详解

### 秒杀下单工作流

```
┌─────────────────────────────────────────────────────────────┐
│ User Request: POST /api/orders/seckill?userId=1              │
│ Body: {productId: 1, quantity: 5}                            │
└────────────────────┬────────────────────────────────────────┘
                     │
        ┌────────────▼────────────┐
        │ 检查幂等性              │
        │ Redis key:              │
        │ order:idempotent:1:1    │
        └─┬──────────────┬────────┘
          │              │
      [存在]          [不存在]
          │              │
        返回             继续
        已有订单         │
                  ┌──────▼──────────┐
                  │ 检查商品存在性  │
                  │ DB: SELECT ...  │
                  └──────┬──────────┘
                         │
                  ┌──────▼────────────────┐
                  │ 检查库存（Redis 优先）│
                  │ GET inventory:1       │
                  │ 对比 quantity vs st   │
                  └──┬───────────┬────────┘
                    │           │
               [不足]│        [充足]
                    │           │
                  返回           │
                  错误    ┌──────▼────────────┐
                         │ 扣减 Redis 库存   │

                         └──────┬────────────┘
                                │
                         ┌──────▼────────────────┐
                         │ 生成雪花 ID          │
                         │ 创建本地订单         │
                         │ status = pending     │
                         │ INSERT into orders   │
                         └──────┬────────────────┘
                                │
                         ┌──────▼────────────────┐
                         │ 发送 Kafka 消息      │
                         │ topic: seckill-orders│
                         │ key: 1_1             │
                         └──────┬────────────────┘
                                │
                    ┌───────────▼──────────┐
                    │ 立即返回给用户ORD   │

                    └──────────────────────┘

                    *** 异步消费 ***
                           │
                    ┌──────▼──────────────────┐
                    │ Kafka Consumer 消费    │
                    │ 反序列化消息           │

                    │ 扣减 DB 库存           │
```

### 幂等性保证

```
┌────────────────────────────────────────────┐
│ User A: 秒杀商品 1，第 1 次                  │
└──────────────────┬─────────────────────────┘
                   │
        ┌──────────▼──────────┐
        │ Redis: setIfAbsent  │
        │ key: order:i:1:1    │ ◀─ [True] 成功，继续下单
        │ value: 1            │
        │ expire: 24h         │
        └─────────────────────┘

     5 分钟后...

┌────────────────────────────────────────────┐
│ User A: 重复秒杀商品 1，第 2 次              │
└──────────────────┬─────────────────────────┘
                   │
        ┌──────────▼──────────┐
        │ Redis: setIfAbsent  │
        │ key: order:i:1:1    │ ◀─ [False] 已存在
        │ 返回已有订单 ID      │    不会创建新订单
        └─────────────────────┘
```

### 库存一致性保证

```
秒杀前: 商品 1 库存 100

┌─────────────────────────────────────────────────────────────┐
│ 并发秒杀 5 个请求（每个扣 20 件）                            │
└──────────────────┬──────────────────────────────────────────┘
                   │
        ┌──────────▼──────────────────┐
        │ Redis 缓存库存扣减          │
        │ inventory:1 = 100           │
        │   ├─ DECRBY 20 → 80         │
        │   ├─ DECRBY 20 → 60         │
        │   ├─ DECRBY 20 → 40         │
        │   ├─ DECRBY 20 → 20         │
        │   ├─ DECRBY 20 → 0          │
        │   └─ DECRBY 20 → -20 ✗ 失败│
        │       回滚上一步             │
        └──────────────────────────────┘
                   │
        ┌──────────▼──────────────────┐
        │ 消息写入 Kafka              │
        │ 4 条成功消息               │
        │ (id, uid, pid, qty)         │
        └──────────────────────────────┘
                   │
        ┌──────────▼──────────────────┐
        │ 后端异步消费 Kafka          │
        │ 逐条处理，扣减 DB 库存      │
        │ product.stock -= 20 × 4     │
        └──────────────────────────────┘
                   │
        最终一致: 库存 = 100 - 80 = 20
```

## 配置文件

### `application.yml` - Kafka 配置
```yaml
spring:
  kafka:
    bootstrap-servers: kafka:9092
    producer:
      key-serializer: org.apache.kafka.common.serialization.StringSerializer
      value-serializer: org.apache.kafka.common.serialization.StringSerializer
      acks: all
      retries: 3
    consumer:
      group-id: seckill-group
      key-deserializer: org.apache.kafka.common.serialization.StringDeserializer
      value-deserializer: org.apache.kafka.common.serialization.StringDeserializer
      auto-offset-reset: earliest
```

### `docker-compose.yml` - Kafka 服务配置
```yaml
zookeeper:
  image: confluentinc/cp-zookeeper:7.5.0
  environment:
    ZOOKEEPER_CLIENT_PORT: 2181

kafka:
  image: confluentinc/cp-kafka:7.5.0
  depends_on:
    - zookeeper
  environment:
    KAFKA_BROKER_ID: 1
    KAFKA_ZOOKEEPER_CONNECT: zookeeper:2181
    KAFKA_ADVERTISED_LISTENERS: PLAINTEXT://kafka:9092
    KAFKA_AUTO_CREATE_TOPICS_ENABLE: "true"
  healthcheck:
    test: ["CMD", "nc", "-z", "localhost", "9092"]
```

## 关键设计决策

### 1. 为什么用 Redis 防重而不是数据库
- 响应速度快（µs 级）
- 支持原子操作 setIfAbsent
- 自动过期（24h），无需手动清理

### 2. 为什么消息 key 用 `{userId}_{productId}`
- 同一用户同一商品的消息保证顺序消费
- 避免并发写入同一订单的竞态条件

### 3. 为什么订单先本地存储再异步处理
- 即使 Kafka 故障，订单不丢失
- 异步处理仅是"状态更新"而非"订单创建"
- 提高系统可用性

### 4. 为什么库存使用 Redis + DB 双重检查
- Redis 保证高速响应
- DB 保证最终一致性
- 防止 Redis 故障导致超卖

## 下一步优化方向

1. **分布式锁**：使用 Redis Lua 脚本实现库存原子扣减
2. **死信队列**：处理失败消息的重试机制
3. **订单状态机**：支持取消、退款等多阶段生命周期
4. **秒杀预热**：提前加载热点商品到 Redis
5. **限流降级**：Guava RateLimiter 或 Sentinel 限流
6. **监控告警**：订单成功率、消费延迟等指标
7. **多地域部署**：跨域 Kafka 同步，支持海量并发
